# 0.2.0 界面改版验收

0.2.0 重做了书架、编辑器、调色盘、笔尖和页面面板；存储格式、OCR 引擎和备份格式与 0.1.0 兼容。

## 自动化

| 验收 | 结果 |
|---|---|
| 离线 Gradle 构建 | `assembleDebug assembleRelease assembleDebugAndroidTest` 通过；构建时校验 OCR 引擎与两个模型摘要 |
| `lintDebug` | 通过，无错误 |
| 系统仪器测试（飞行模式，AOSP Android 12 / API 31，x86_64） | `OK (8 tests)`：无网络权限、笔迹/撤销/重做、PDF 像素回读、中英文印刷体 OCR、含合成 AAC 与闪卡的备份恢复、原子保存、拒绝不合法备份、混合页尺寸 PDF |
| 界面流程（飞行模式模拟器） | 通过：图标新建、书写、页内文字、添加页面、强停重启、搜索、删除；只操作唯一命名的合成笔记 |
| 布局（模拟器） | 竖屏 720×1280、横屏 1280×720、转回竖屏、360 dp（1080×2400 @480 dpi）书架均无越界；横屏书写可保存 |
| 两个 APK 的实际权限 | `aapt dump badging` 仅列出 `RECORD_AUDIO`；无 `INTERNET` 或 `ACCESS_NETWORK_STATE`；测试签名验证通过 |

## 真机检查（设备所有者授权）

Xiaomi arm64 设备，Android 16（API 36），1220×2712、480 dpi。真机上完成了 0.2.0 界面流程、横竖屏/360 dp 布局、离线 OCR 面板（成功识别页面印刷文字）、蓝色色位应用和笔尖粗细调整后实际书写。随后只做了色位尺寸、面板导航栏留白和工具栏宽度等外观微调，最终构建的回归测试在模拟器完成；微调后未重新在真机运行整套自动化。

HyperOS 的“USB 安装”校验拒绝了仅用于测试的 instrumentation APK 重新安装（主应用安装不受影响），因此最终构建的系统测试在隔离模拟器完成。未改动手机的安装安全设置。

实体触控笔的压感手感、真实麦克风采音质量、系统文件选择器的导入/导出界面未做硬件验证。
